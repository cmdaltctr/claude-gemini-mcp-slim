Title: 002.1-Architectural Problems and Refactoring Initiative
Date: 2025-07-22 to 2025-08-03
Decision Maker: Dr Muhammad Aizat Hawari
Status: Accepted

## Context

The Claude-Gemini MCP project identified significant architectural problems that required comprehensive refactoring. This initiative began on **July 22, 2025** (earliest commit: `b4e0124` at 13:12:42 +0800) and addressed fundamental design violations that were impacting maintainability, testability, and security.

## Problems Identified

### 1. Monolithic Server Architecture

The `gemini_mcp_server.py` file was handling multiple responsibilities simultaneously, creating a monolithic architecture that violated fundamental software engineering principles.

**Specific Issues**:
- Server module contained both MCP communication logic AND direct AI API interaction logic
- Functions like `execute_gemini_api()` and `execute_gemini_cli_streaming()` were embedded within the server module
- This dual responsibility created tight coupling between protocol handling and AI backend interactions

### 2. Violation of Single Responsibility Principle (SRP)

Core modules were violating the Single Responsibility Principle by managing multiple, unrelated concerns within single files.

**Specific Issues**:
- The server module was simultaneously acting as a communicator, AI specialist, and workflow orchestrator
- No clear separation between MCP protocol handling and AI backend management
- Changes to AI interaction logic required modifications to the MCP communication layer

### 3. Scattered Configuration Management

Configuration values were inconsistently managed across the codebase, creating maintenance challenges and potential security vulnerabilities.

**Specific Issues**:
- Configuration values were scattered across multiple files
- Some values were hard-coded, others read from environment variables
- No consistent pattern for accessing configuration
- Direct use of `os.getenv()` calls throughout the codebase

### 4. Inconsistent Security and Error Handling

Security and error handling mechanisms were implemented inconsistently across the codebase, creating potential vulnerabilities and unpredictable behavior.

**Specific Issues**:
- Security concerns were handled ad-hoc throughout the codebase
- No consistent pattern for input sanitization or path validation
- Error handling was inconsistent with some errors not properly caught or reported
- Missing centralized security functions

## Decision

We decided to implement a comprehensive architectural refactoring to address these fundamental problems through:

1. **Decoupled Module Pattern Implementation**
2. **Centralized Configuration Management System**
3. **Dedicated Security Module Creation**
4. **Enhanced Error Handling Standardization**

## Consequences

### Positive Consequences

**1. Decoupled Module Pattern Implementation**:
- **The Communicator** (`gemini_mcp_server.py`): Focuses solely on MCP requests and responses
- **The AI Specialist** (`gemini_helper.py`): Manages all Gemini backend interactions
- **Pre-Processing and Post-Processing Engines** (`helpers/` directory): Specialized modules for specific tasks

**2. Centralized Configuration Management**:
- Clear accessor functions (`cfg.get_model()`, `cfg.get_limit()`, etc.)
- Well-defined load precedence (explicit args > env vars > config.json > defaults)
- Thread-safe caching for performance
- Elimination of direct `os.getenv()` calls

**3. Dedicated Security Module**:
- `sanitize_for_prompt()` - Prevents prompt injection attacks
- `validate_path_security()` - Prevents path traversal attacks
- Centralized security function management (implemented in `helpers/security.py`)

**4. Enhanced Error Handling**:
- Proper redaction of sensitive information in error messages
- Clear fallback mechanisms when primary methods fail
- Graceful error handling throughout the AI interaction pipeline

### Challenges

- **Initial Refactoring Effort**: Significant code restructuring required across multiple modules
- **Testing Updates**: Comprehensive test suite updates needed to support new architecture
- **Documentation Updates**: All documentation needed to reflect new architectural patterns

## Alignment with Golden Rules

This architectural refactoring directly implements the principles outlined in the project's Golden Rules:

1. **Core Philosophy**: Acting as an intelligent orchestrator rather than a simple bridge
2. **Decoupled Module Pattern**: Strict adherence to separation between Communicator, AI Specialist, and Processing Engines
3. **Configuration Management**: Centralized configuration system for all settings
4. **Security**: Dedicated security functions for input sanitization and validation

## Current Status

**Completion Status**: Task 1 core objectives achieved with subtasks completion rate of 80% (13/16 subtasks completed).

This comprehensive refactoring has transformed the codebase from a monolithic architecture into a maintainable, testable, and secure modular system that supports the project's evolution toward sophisticated AI-driven development workflows and positions the project for the planned evolution toward the Agentic Collaboration Protocol (ACP).

## References to Central Config & Security Modules

This ADR establishes the foundation for:
- **Central Configuration Module** (`config.py`): Centralized configuration management with accessor functions
- **Security Module** (`helpers/security.py`): Centralized security functions for input sanitization and path validation
- **AI Specialist Module** (`gemini_helper.py`): Isolated AI backend interaction management

These modules form the core infrastructure referenced throughout the project architecture and ensure consistent patterns for configuration access and security handling.
